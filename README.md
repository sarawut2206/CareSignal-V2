## ปัญหาที่แก้

> **“การล้มหนึ่งครั้งของผู้สูงอายุ อาจเปลี่ยนจากการดูแลที่บ้าน เป็นค่าใช้จ่ายระยะยาวของครอบครัวและบริษัทประกัน — เราจึงตรวจจับสัญญาณการเสื่อมถอย ก่อนเกิดเหตุ”**

ผู้สูงอายุราว 1 ใน 3 ล้มอย่างน้อยปีละครั้ง และการล้มคือจุดเริ่มต้นที่พบบ่อยที่สุดของภาวะพึ่งพิง (WHO Step Safely 2021) ขณะที่บริษัทประกันไทยออกผลิตภัณฑ์ดูแลระยะยาว (Long-Term Care) ได้ยาก เพราะ**ไม่มีข้อมูลสมรรถภาพของคนไทยแบบต่อเนื่อง** — ไม่มีตารางอุบัติการณ์ LTC มาตรฐาน ไม่รู้ว่าใครกำลังถดถอย และรู้ตัวอีกทีคือตอนเคลม CareSignal สร้างข้อมูลชุดนั้นจากการประเมินมาตรฐาน (Five-Times Sit-to-Stand, Timed Up & Go) ที่ทำเองได้ที่บ้านด้วยกล้องมือถือ

**รู้ก่อนพึ่งพิง · ป้องกันก่อนเคลม**

## ผลลัพธ์ที่นำเสนอเป็นตัวเลข

แยกชัดเจนระหว่างสิ่งที่กลไกในระบบ**วัดได้แล้ววันนี้** กับ**เป้าหมายที่ประกาศเกณฑ์ล่วงหน้า**เพื่อพิสูจน์ในนำร่อง 30–100 ราย — ไม่นำตัวเลขสมมติมาแสดงเป็นผลจริง

| ตัวชี้วัด | ตัวเลข | สถานะ |
|---|---|---|
| จับสัญญาณเสี่ยงก่อนเกิดเหตุ | **21–90 วัน** ตามรอบประเมินของระดับสัญญาณ + แจ้งทันทีเมื่อช้าลงเกิน MCID 2.3 วิ | กลไกทำงานแล้ว · จำนวนวันนำหน้าการล้มจริงวัดในนำร่อง |
| การล้มในกลุ่มเข้าโปรแกรมป้องกัน | **−20–25%** (Cochrane 2019; Otago) → ลดเหตุส่งโรงพยาบาลตามสัดส่วน | อ้างอิงวรรณกรรม ไม่ใช่ผลของระบบนี้เอง |
| ต้นทุนสินไหม LTC (โมเดลฐาน) | **−12%** (เข้าโปรแกรม 60% × ประสิทธิผล 20%) เทียบเพิ่มกับพอร์ตไม่คัดกรอง +25% adverse selection | สมมติฐานโมเดล ปรับได้ 14 ตัวแปร |
| ภาระคัดกรองของ Care Manager | **~70%** ลดลง — เอนจินกฎ triage ให้รีวิวเฉพาะเคสเข้าเกณฑ์ | กลไกทำงานแล้ว · เวลาจริงวัดในนำร่อง |
| กลับมาประเมินซ้ำใน 90 วัน | **≥60%** — ระบบเทียบคะแนนกับ baseline ตัวเองอัตโนมัติ (กฎ R4) | เกณฑ์ผ่านประกาศล่วงหน้า (ตัวชี้วัด #6 ของแผนนำร่อง) |

## หลักการที่เขียนอยู่ในโค้ด (ไม่ใช่คำสัญญาในเอกสาร)

1. **ไม่ส่งภาพออกจากเครื่อง** — กล้องประมวลผลด้วย MediaPipe Pose บนเครื่องผู้ใช้ ระบบเก็บเฉพาะตัวเลข (เวลา จำนวนครั้ง คะแนน)
   *ตรวจสอบได้เอง:* ค้นทั้งโปรเจกต์จะไม่พบ `fetch(` / `XMLHttpRequest` / `sendBeacon` / `WebSocket` แม้แต่ตัวเดียว — การเชื่อมต่อภายนอกมีเพียงการ**ดาวน์โหลด**ไลบรารี โมเดล และฟอนต์
2. **ลดเบี้ยทางเดียว** — `discount:{4:.15, 3:.08, 2:0, 1:0}` ไม่มีเส้นทางใดในโค้ดที่เพิ่มเบี้ยหรือปฏิเสธความคุ้มครองจากคะแนนที่แย่ลง
3. **มนุษย์ตัดสินเสมอ** — AI คัดกรองและรวบรวมหลักฐาน การส่งต่อและสินไหมทุกกรณีต้องกดยืนยันโดยผู้เชี่ยวชาญ และทุกการตัดสินใจถูกบันทึกใน audit log ที่ผู้ใช้เปิดดูได้
4. **แยก AI ออกจากกฎ** — กล้องตรวจจับท่าทางคือ AI จริง ส่วนการอ่านแนวโน้มใช้กฎ R1–R7 ที่อ้างอิงงานวิจัยและอธิบายเหตุผลเป็นตัวเลขได้ทุกคำเตือน ไม่เรียกรวมว่า "AI ทำนายโรค"
5. **เทียบกับตัวเองในอดีต ไม่ใช่ค่าเฉลี่ยคนอื่น** — ลดอคติระหว่างเพศ/ช่วงอายุโดยการออกแบบ

## เทคนิคที่ใช้

- **MediaPipe Pose Landmarker** (33 จุด, ประมวลผลในเครื่อง, WebGL GPU)
- **ตัววัดไม่ขึ้นกับระยะกล้อง:** `M = (ระยะข้อเท้า−สะโพก) ÷ (ระยะข้อเท้า−ไหล่)` + สอบเทียบท่านั่ง/ยืนรายบุคคล
- **ตัวนับครั้ง:** state machine พร้อม hysteresis (ขึ้น 68% / ลง 36% ของช่วงสอบเทียบ) + moving average 5 เฟรม กันนับซ้ำจากการสั่น
- **เกณฑ์เวลาอ้างอิงประชากรไทย:** 10.0 / 11.5 / 12.1 วินาที ตามช่วงอายุ (Poncumhak 2014; Intaruk 2021) · MCID ≈ 2.3 วิ (Meretta 2006; Goldberg 2012)
- **PWA เต็มรูปแบบ:** ติดตั้งลงเครื่องได้ ใช้ออฟไลน์ได้หลังเปิดครั้งแรก (โมเดล AI ถูกแคชไว้)
- **ทางสำรองทุกจุด:** กล้องเปิดไม่ได้ / โมเดลโหลดไม่ได้ / นับไม่ขึ้นกลางคัน → จับเวลาเองแล้วกรอกตัวเลข ระบบให้คะแนนและวิเคราะห์เหมือนกันทุกอย่าง และบันทึกไว้เสมอว่าครั้งนั้นวัดด้วยวิธีใด

## 📲 ติดตั้งเป็นแอปบนมือถือ

CareSignal เป็น **Progressive Web App (PWA) เต็มรูปแบบ** — ติดตั้งได้เหมือนแอปจริง ไอคอนบนหน้าจอ เปิดเต็มจอไม่มีแถบเบราว์เซอร์ และ**ใช้ได้แม้ไม่มีอินเทอร์เน็ต**หลังเปิดครั้งแรก

| แพลตฟอร์ม | วิธีติดตั้ง |
|---|---|
| **Android (Chrome)** | เปิดเว็บ → แตะปุ่ม "ติดตั้ง" ที่ระบบเสนอ หรือเมนู ⋮ → "ติดตั้งแอป" |
| **iPhone / iPad (Safari)** | ปุ่มแชร์ → "เพิ่มลงหน้าจอโฮม" → เพิ่ม (แอปมีตัวช่วยแนะนำขั้นตอนในตัว) |
| **Windows / Mac (Chrome/Edge)** | ไอคอน ⊕ ในแถบที่อยู่ → "ติดตั้ง" |

เมื่อติดตั้งแล้ว กดค้างที่ไอคอนจะมี **ทางลัด** ไปยัง "เริ่มประเมินด้วยกล้อง", "แอปสมาชิก" และ "โมเดลธุรกิจ" ได้ทันที

> ต้องการแพ็กเป็นไฟล์ .aab ขึ้น **Google Play Store**? ใช้ [PWABuilder](https://www.pwabuilder.com) กรอก URL ของเว็บนี้ ระบบจะสร้างแพ็กเกจ Trusted Web Activity ให้อัตโนมัติ — manifest ของโปรเจกต์นี้ผ่านเงื่อนไขครบแล้ว

## มาตรฐานที่ระบบผ่าน

- **PWA installable** — manifest ครบ (id, icons maskable, shortcuts, display_override) + Service Worker offline ที่ทดสอบแล้ว + ระบบแจ้งอัปเดตเวอร์ชันอัตโนมัติ
- **Content Security Policy** — ทุกหน้าประกาศ CSP จำกัดแหล่งสคริปต์/การเชื่อมต่อไว้เฉพาะ CDN ที่จำเป็น, `object-src 'none'`, `base-uri 'self'` — ลดพื้นผิวการโจมตี XSS
- **การเข้าถึง (WCAG 2.1)** — dialog มี focus management + ปิดด้วย Escape, toast เป็น `aria-live`, แท็บมี `aria-selected`, รองรับ `prefers-reduced-motion`, ตัวอักษรและปุ่มขนาดใหญ่ทั้งระบบสำหรับผู้สูงอายุ
- **SEO / Social** — meta description ทุกหน้า + Open Graph สำหรับการแชร์ลิงก์

## สถานะของงานและข้อจำกัด (ประกาศอย่างเปิดเผย)

- ระบบทำงานได้จริงทั้งหมด แต่**ยังไม่ผ่านการทดสอบภาคสนามกับผู้สูงอายุจริง** — แผนวัดผลนำร่อง 30–100 ราย พร้อมเกณฑ์ผ่านที่ประกาศล่วงหน้า อยู่ในหน้า "แผนวัดผลนำร่อง" ของเว็บแพลตฟอร์ม
- ตัวเลขการเงินในโมเดลผู้ประกอบการเป็น**สมมติฐานที่ประกาศชัดและปรับได้ทุกตัวแปร** อัตราลดอุบัติการณ์อ้างอิงวรรณกรรมต่างประเทศ ไม่ใช่ผลของระบบนี้เอง
- เดโมนี้เป็น client-side ทั้งหมด (GitHub Pages ไม่มี backend) — ฐานข้อมูลกลาง คิวเคสข้ามเครื่อง และระบบสิทธิ์ผู้ใช้จริง ต้องมี backend ในเฟสถัดไป ชั้นข้อมูล (`DB` adapter) ออกแบบให้สลับเป็น REST API ได้ทันที
- หน้า "ผู้เชี่ยวชาญ" และ "บริษัทประกัน" เปิดให้ชมได้เพื่อการนำเสนอ โดยมีประตูประกาศบทบาทกำกับ — ระบบจริงใช้ role-based access
- **ระบบนี้เป็นเครื่องมือสนับสนุนการตัดสินใจ ไม่ใช่การวินิจฉัยทางการแพทย์** และการเสนอขายประกันภัยจริงต้องดำเนินการโดยบริษัทที่ได้รับใบอนุญาตจากสำนักงาน คปภ.

## ความเป็นส่วนตัว (PDPA)

- ขอความยินยอมชัดเจนก่อนเก็บข้อมูล และขอแยกต่างหากสำหรับข้อมูลชีวมิติ (มาตรา 26) ซึ่งปฏิเสธได้โดยยังใช้ระบบได้ตามปกติ
- ลายเซ็นใบหน้า (ตัวเลข 6 ค่า ไม่ใช่ภาพ) เก็บในเครื่องผู้ใช้เท่านั้น ไม่ผ่านชั้นฐานข้อมูลใด
- ผู้ใช้ถอนความยินยอมและลบข้อมูลทั้งหมดได้ทุกเมื่อในหน้าตั้งค่า
- ข้อมูลที่แชร์ให้แดชบอร์ดพอร์ตเป็นสรุป **แบบแฝงชื่อ (pseudonymised)** — รหัสสุ่มแทนชื่อจริง ช่วงอายุ เพศ ระดับสัญญาณ ตามหลัก data minimization และปิดการแชร์ได้
- **เราเรียกข้อมูลชุดนี้ว่า "แฝงชื่อ" ไม่ใช่ "นิรนาม" โดยตั้งใจ** เพราะยังมีรหัสอ้างอิงที่เชื่อมกลับได้ จึงยังเป็นข้อมูลส่วนบุคคลที่อยู่ในบังคับของ PDPA ทุกมาตรา — การเรียกว่า anonymised จะทำให้เข้าใจผิดว่าอยู่นอกขอบเขตกฎหมาย
